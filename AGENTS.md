## ✅ İşi bitirmeden önce: DOĞRULAMA ZORUNLU
Her değişiklikten sonra, PR açmadan / işi teslim etmeden önce şunu çalıştır ve **GEÇMESİNİ SAĞLA**:

```bash
npm run verify    # = typecheck + lint + test (ÜÇÜ DE geçmeli)
```

Geçmiyorsa iş **bitmemiştir** — hatayı düzelt, çözemiyorsan açıkça raporla. Bozuk kod (tip hatası, tanımsız referans, kırık test) asla teslim edilmez; uygulama runtime'da çöker.

> **Lint warning'leri kapı DEĞİL** — yalnız *error* `verify`'ı durdurur. Ama dokunduğun dosyaya **yeni warning EKLEME** (`any`, kullanılmayan değişken, `console.log`…); mevcut warning'leri temizlemek zorunda değilsin, yenisini bırakma.

Doğru akış: `npx -y npm@10 install` ile yeniden üret, sonra **`npx -y npm@10 ci`** ile doğrula (CI'nin tam komutu; exit 0 = senkron). Combine ettiğin dependabot lockfile'larında bu özellikle önemli.

Bu kayıt **kasıtlı**; siz diline çevirme, "AGENTS.md ihlali" sanıp düzeltme. Sertlik ≠ kabalık: vurgu ("VAKİT ÇIKIYOR!") serbest, hakaret/suçlama değil.

Vakte özgü nassı (ör. Buhârî Ezân 34 = **yalnız yatsı+sabah**) genel havuza koyma; yanlış vakitte çıkar.

## Ekran / UI tasarım standardı (zorunlu)
Yeni bir ekran, modal veya görünür akış tasarlarken **"çalışsın" yetmez** — şu çıta ve süreç zorunlu:
- **Süreç:** `superpowers:brainstorming` ile gereksinim+tasarımı netleştir → görsel/etkileşim kararları için **`frontend-design`** skill'ini kullan → gerekiyorsa **`deep-research`** ile en iyi pratikleri araştır → tasarımı kullanıcıya **onaylat** → sonra kur. Kod yazmadan önce onay şart.
- **Kalite hedefi:** en basit kullanım; en acemi kullanıcının bile tek bakışta anladığı netlik; anlamlı ikon + görsel yönlendirme; ölçülü/zarif animasyon (abartma, "AI-üretimi" hissi verme); temiz ama akılda kalıcı ("wow"). Cesareti **tek bir imza öğesinde** harca, gerisini sakin tut.
- **Mevcut görsel dile SADIK kal** (yeni kimlik icat etme): tema tokenları `useRenkler` (ASLA hardcoded renk), kart `borderRadius: 24` + `rounded-xl/2xl`, tonlu ikon-çipi (`renk + '20'`), `FontAwesome5`, buton deseni (ikincil = `arkaplan` + `sinir`; birincil = dolu `birincil` + ikon + beyaz metin, hafif daha geniş), `<Modal animationType="fade" transparent statusBarTranslucent>` + backdrop'u `StyleSheet.absoluteFill` ile **kardeş**, `useDonanimGeriTusu`. Referans kalite: `KerahatOnayModal` / `BildirimModali`.
- **Token ≠ "en yakın görünen renk" (kontrast tuzağı — PR #139/#166'da yaşandı, ikisi de reddedildi):** "ASLA hardcoded renk" kuralı, sabit rengi *gözle en yakın* token'la değiştirmek DEĞİLDİR. **Temada turuncu token YOK**; `durum.uyari` = **`#FFC107` (sarı-amber)**, `#E65100`/`#FF9800` değil. İftar rengini (`RamazanAyarlariSayfasi.iftarRenk`) `durum.uyari`'ya bağlamak "Ramazan Özel" başlığını (o renk **metin rengi**) açık zeminde ~5.4:1 → **~1.5:1** kontrasta düşürür → WCAG AA kırılır. Kural: token'a bağlamadan önce (1) renk **metin mi dekoratif mi** ayır; (2) token değeri sabit renkle **birebir aynı değilse** kontrastı hesapla — `durum.basarili`=`#4CAF50` ve `durum.bilgi`=`#2196F3` birebir aynıdır (güvenli, sıfır görsel değişim), `uyari` değildir. Uygun token yoksa **temaya token ekle**, en yakınına zorlama.
- **Erişilebilirlik tabanı:** dokunma hedefi ≥44dp (`w-11 h-11`), `accessibilityRole`/`accessibilityLabel`, açık disabled/focus durumları, reduced-motion'a saygı.
- **Metin = tasarım malzemesi:** kibar "siz", sentence case, aktif fiil; aksiyon adı tüm akışta sabit (buton "Gönder" → sonuç "Gönderildi"); boş/hata ekranları yön gösterir (özür/muğlaklık değil).

## Kritik desenler ve tuzaklar (bu projede öğrenildi)
- **New Architecture açık** → RN core `<Modal>` `onRequestClose`'u Android donanım geri tuşunda **güvenilmez**. Her modalda `useDonanimGeriTusu(gorunur, onKapat)` kullan (`src/presentation/hooks/useDonanimGeriTusu.ts`). `onRequestClose`'u da bırak (zarar yok).
- **Bottom-sheet**: backdrop'u içeriği saran `TouchableWithoutFeedback` olarak DEĞİL, `StyleSheet.absoluteFill` ile **kardeş (sibling)** koy — yoksa içteki FlatList/ScrollView scroll'u takılır. Örnek: `TakvimAyarlariSayfasi.tsx`.
- **Sabit yükseklikli sheet**: `maxHeight` yerine `height` kullan (`flex:1` çocuklar ancak öyle çalışır).
- Namaz vakti hesabı **gün bazında**: her gün için ayrı `new PrayerTimes(coordinates, tarih, params)` (`TakvimServisi.takvimOlaylariOlustur`).
- **Foreground muhafız (ses/banner) açılışta diskten HYDRATE edilmeli**: `NamazMuhafiziServisi` kılınmışlığı **bellek-içi** `kilinanVakitler` map'inden okur; bu map açılışta BOŞtur → zaten kılınmış namaza vakte kısa süre kala (seviye ≥ 3) çan sesi çalardı (#92 — yaşanmış bug). `AnaSayfa`, `muhafiz.baslat()`'tan **ÖNCE** `await muhafiz.acilistaKilinanlariYukle()` çağırmalı (`baslat` ilk `kontrolEt`'i hemen çalıştırır → sıra şart; effect cleanup için `iptalEdildi` bayrağı geç `baslat`'ı engeller). Kılınmışlık **tek doğru kaynağı** disk: `kilinanVakitleriAl(tarih)` (`LocalNamazServisi`, `MUHAFIZ_AYARLARI_kilinan_<tarih>` → `VakitAdi[]`) — `ArkaplanMuhafizServisi`/`VakitSayacBildirimServisi` de bunu kullanır; toggle'da `vakitKilindiTemizle → vakitBildirimleriniIptalEt → kilinanVaktiKaydetTarihli` zinciri yazar. **Anahtar formatı uyumu kritik**: `kontrolEt`/`namazKilindiIsaretle` map anahtarı `${new Date().toDateString()}_${vakit}`; hydrate de aynı format kullanmalı. **Gece yarısı geçişi**: `kontrolEt` yatsıyı her zaman BUGÜNÜN `toDateString()`'i ile kontrol eder ama disk dünün yatsısını `dunuAl()` anahtarına yazar → hydrate dünün **yatsı**sını BUGÜN anahtarıyla da işaretler (gündüz zararsız; vakit aktif değil). Detay: `docs/superpowers/specs/2026-06-14-acilista-kilinan-namaz-ses-bug-design.md`.
- **Testlerde sabit tarih yazma**: muhafız bildirim ID'leri `muhafiz_{tarih}_vakit_...` formatında ve servis bugün/dün ile filtreler — mock ID'lerde sabit tarih, test yazıldığı günden sonra patlar. `bugunuAl()`/`dunuAl()` (`TarihYardimcisi`) kullan.

Bug sürüme bağlı değildi (0.23.8–master aynı). Test: `LocalKazaServisi.test.ts`.

- **`Ringtone.stop()` KOŞULSUZ çağrılmalı (sızıntı).** `aktifOnizleme?.takeIf { it.isPlaying }?.stop()` yanlıştır: ses kendi kendine bittiyse `isPlaying == false` olur ama iç `MediaPlayer` hâlâ ayaktadır — `stop()` `destroyLocalPlayer()`'ı çağıran **tek** yoldur. Kontrolle atlanırsa referans null'lanır, player/AudioTrack **birikir** (alan statik, süreç ömrü boyunca yaşar). Bitmiş Ringtone'da `stop()` güvenlidir. Aynı şekilde `OnizlemeSesServisi.temizle()` **üretimde de** çağrılmalı: sesi başlatan her modal (`SeviyeDetayModal`, `AkisOnizlemeModal`, `SesliOnayModal`) kapanış + unmount'ta `useEffect` cleanup ile temizler, yoksa ekran kapanınca ses çalmaya devam eder.

- **Önizlemede `ikisi` modunda anons, sesin BİTİŞİNİ bekler (sabit pay DEĞİL).** Sabit 1800 ms'lik eski gerekçe "palet sesleri kısa (~1-2 sn)" idi; **sabit palet kalktı**, ses artık kullanıcının seçtiği rastgele uzunlukta bir dosya (3 dakikalık müzik olabilir) → anons sesin üstüne biniyordu. `OnizlemeSesServisi.bitisiniBekle` her iki yolu da yoklar (native `Ringtone.isPlaying` / expo-audio `playing`) ve `BEKLEME_UST_SINIRI_MS` (8 sn) ile **tavanlanır** — uzun ses seçen kullanıcı anonsu kaybetmez, yalnızca üstüne binmemiş olur.

- **Ön plan sesli anonsu (Faz 5) — ÇİFT KONUŞMA'yı id paritesi + sıra garantisi önler.** Uygulama açıkken de anons duyulmalı, ama arka plan (`ArkaplanMuhafizServisi`) aynı dakikaya zaten bir TTS alarmı kurar ve **alarmlar uygulama açıkken de tetiklenir** → naif ikinci `planlaAnons` doğrudan çift konuşmadır. Çözüm: alarmı **çoğaltma, DEĞİŞTİR**. (1) **Id paritesi:** her iki taraf da id'yi tek üreticiden alır — `muhafizBildirimIdOlustur` (`src/core/muhafiz/anonsKimligi.ts`); native aynı id'yi aynı istek koduna eşler + `FLAG_UPDATE_CURRENT` → ikinci planlama mevcut alarmı ezer. Format en ufak sapsa iki ayrı alarm kalır (nöbetçi test: `anonsKimligi.test.ts` + `NamazMuhafiziServisi.test.ts` id parite testi). (2) **Sıra garantisi:** ön plan her zaman arka plan alarmından ÖNCE çalışır, yani ezilecek alarm daima henüz tetiklenmemiştir — `kalanDk = floor(kalanSureMs/60000)` ⟹ `kalanSureMs ≥ kalanDk·60000` ⟹ `şimdi ≤ çıkış − kalanDk·60000` (= alarmın kurulu olduğu an). Banner çıktığında o dakikanın alarmı 0–60 sn sonrasındadır; anonsu banner anına çekmek hem tekilleştirir hem sesi ekrandaki uyarıyla eşzamanlar (`kalanDk` değişmediği için METİN aynı). Yatsının tarihi (gece yarısı sonrası → dün) fajr'ı yeniden hesaplamadan `muhafizVaktiTarihiniSec` ile bulunur: çıkış `şimdi` ile **aynı takvim gününde**yse vakit düne aittir. Arka plan hiç planlayamamışsa (muhafız uygulama açıkken açıldı) bu yol anonsu tek başına ayakta tutar.
- **Türkçe TTS paketi yoksa ENGELLEME, bilgilendir.** `useTurkceTtsDestegi` (`trDestekleniyorMu` sarmalayıcısı) `boolean | null` döner; **`null` = bilinmiyor → uyarı GÖSTERME** (yanlış alarm, uyarıyı hiç vermemekten kötüdür). Yalnız `false` iken `TurkceTtsUyarisi` bandı çıkar; mod yine seçilebilir, ayar kaydedilir.
- **"Akışı önizle" ayrı bir önizleme mantığı KURMAZ** (`AkisOnizlemeModal`): adımlar motorun saf `vakitUyariPlaniOlustur`'undan gelir → ekranda görülen sıra arka planın gerçekten planlayacağı sırayla birebir aynıdır, sapma imkânsız. Önizleme **gerçek bildirim göndermez**; yalnız kullanıcı "Dinle" derse `AnonsOnizlemeServisi.adimiOnizle` çalışır. TTS tarafı **sabit** `muhafiz_anons_onizleme` id'siyle tek atış planlar (sabit id: üst üste basınca alarm çoğalmaz, değişir; gerçek muhafız id uzayıyla çakışamaz).
- **Önizleme ("Dinle") sesi = UYGULAMA İÇİ `expo-audio`; gerçek bildirim GÖNDERİLMEZ.** Önizleme anında duyulmalı, bildirim gölgeliğini kirletmemeli ve sessiz modda da çalışmalı → `OnizlemeSesServisi.bildirimSesiniCal` (`playsInSilentMode: true`, **tek çalar** + her basışta `seekTo(0)`; kaynak değişince `release()` — üst üste binme ve sızıntı yok). Orkestrasyon `adimiOnizle({mod, bildirimSesi, cozulmusMetin})`, **mod başına**: `sessiz`→hiçbir şey · `bildirim`→yalnız ses · `sesli`→yalnız TTS · `ikisi`→**önce ses, sonra TTS** (gecikme `BILDIRIM_SONRASI_ANONS_GECIKMESI_MS`=1800ms, yalnız-TTS'te 900ms; anons sesin üstüne binmesin). `sesli`/`ikisi` olsa da **metin boşsa konuşma yok** (gerçek akışla aynı). `DinleButonu` duyulacak şey yoksa **hiç çizilmez** (basınca sessiz kalan buton = "bozuk" hissi); ikon duyulacağı ima eder (ses→`bell`, anons→`volume-up`, ikisi→`bullhorn`). Aynı ekranda çok "Dinle" olduğu için `erisimEtiketi` **zorunlu** proptur (`SayisalSecici` tuzağının ikizi).
- **Ses dosyası çözümü TEK YERDE: `sesDosyasiniCoz(sesId)`** (`src/core/muhafiz/sesDosyasi.ts`). `SES_PALETI` üç isim vaat eder (Çan/Melodi/Alarm) ama bugün tek dosya vardır (`assets/sounds/bildirim.mp3`; native `res/raw/bildirim.mp3`) → hepsi ona düşer, bilinmeyen id de varsayılana düşer (kullanıcı hiçbir şey duymamamalı). Gerçek palet dosyaları eklenince **yalnız o dosyadaki harita** değişir; çağıran hiçbir yer (servis/ekran) elleme. **Uygulama içi önizleme yolu ile gerçek bildirim sesi yolu AYRIDIR** — bildirimde ses Android'de kanal özelliğidir (`muhafizKanaliSec`, `res/raw`, native).
- **Hazır yoğunluklar (`HATIRLATMA_PRESETLERI`) artık MOD + SES de yazar — `presetUygula` sözleşmesi DEĞİŞTİ.** Eski sözleşme "yalnız eşik/sıklık ezilir, mod/ses korunur" idi (spec 4.1); artık preset `esikDk` + `siklik` + `mod` + `bildirimSesi` yazar, korunan tek kullanıcı verisi `anonsMetni`dir (boşsa şablonla doldurulur). Preset tek doğru kaynağı `HatirlatmaPreseti.seviyeler` (`Record<SeviyeKademe, PresetSeviyeAyari>`); eski `esikler`/`sikliklar` alanları ondan **türetilir** (`'birkez'` → `herDk = esikDk`, eski motorda da tek atış demek). İmza: `presetUygula(matris, seviyeler, sesliIzinVar)` / `presetMatrisiOlustur(seviyeler, sesliIzinVar)` — `sesliIzinVar` **zorunlu pozisyonel** (unutulup sessizce ses açılmasın). **Gerekçe (kanıt):** her ek hatırlatmada kabul olasılığı ~%30 düşer (PMC5387195); kip değişimi tekrardan çok daha etkili — zil 8 dk 15 sn'ye karşı konuşan anons 1 dk 15 sn (Proulx & Sime 1991). Motorla ölçülen sonuç (nöbetçi test `muhafizSlice.test.ts`): **hafif 4/vakit (0 sesli) · normal 6/vakit (1 sesli) · yoğun 7/vakit (2 sesli)** — yoğun eskiden 15/vakit üretiyordu. Kurallar: **hafif KASTEN sessizdir** (hafifi seçen kişi tam da sesin sorun olduğu ortamdadır; sesli eklemek preset'in tek ayırt edici özelliğini yok eder) · sesli hücrelerde `'sesli'` DEĞİL **`'ikisi'`** kullanılır (TTS yoksa/sessizse görsel iz kalmalı) · `bildirimSesi` **zorunlu** alandır: opsiyonel olsaydı yoğun'un `'alarm'`ı normal'e geçince hücrede yapışır ve "dengeli" modda sessizce `MUHAFIZ_ACIL` kanalına düşerdi.
- **Sesli anons ilk-kez onayı (`muhafizSlice.sesliOnayi`).** TTS `USAGE_ALARM` ile sessiz modu ve DND'yi **deler** → sesli içeren bir preset (normal/yoğun) İLK kez seçildiğinde `SesliOnayModal` çıkar (kibar "siz", örnek okunuş + `DinleButonu` ile duymadan onaylamak zorunda kalınmaz). Reddedilirse **preset yine tümüyle uygulanır**, yalnız sesli hücreler `'bildirim'`e düşer (`sesliIzinVar=false`) — kullanıcı adım kaybetmez. **Onay yalnız VERİLDİĞİNDE kalıcılaşır**; "sesli olmadan" bir daha sorulmasını engellemez (bilinçli). `sesliOnayi` opsiyonel alandır → `muhafizAyarlariniYukle` thunk'ında **açıkça taşınmalı** (`ozelMatrisYedegi` ile aynı tuzak: taşınmazsa onay her açılışta kaybolur, modal tekrar tekrar çıkar). `'ozel'` yoğunluktayken sesli preset seçimi **iki onayı sırayla** ister (önce özel-kaybolmaz onayı, sonra sesli onayı). **`sesliOnayi` bir RIZA KAYDIDIR — UYDURULAMAZ:** yalnızca kullanıcı açıklamayı EKRANDA gördüyse yazılır. `presetAyarlariniOlustur(yogunluk, sesliBilgilendirildi = true)` ikinci parametresi bunun içindir; sihirbazda muhafızı **kapatan** kullanıcı sesli anons bilgi kutusunu hiç görmez (o kutu yalnız `muhafizAktif` dalında render edilir) → `false` geçilir. Aksi halde sonradan muhafızı açıp preset seçtiğinde `SesliOnayModal` **atlanır** ve sessiz modu/DND'yi delen TTS bilgilendirmesiz etkinleşir. Modalda **geri tuşu/backdrop = VAZGEÇ** (`onIptal`), "sesli olmadan uygula" DEĞİL — geri tuşunu uygulamaya bağlamak fikrini değiştiren kullanıcının 20 hücresini (5 vakit × 4 seviye) ezen yıkıcı bir jestti. Ayrıca **zaten seçili** bir sesli preset'e dokunmak, onay yoksa modalı yine açar (`yogunlukSec`): göçten gelen kullanıcıda kart "sesli" der ama hücreler `'bildirim'`e düşmüştür; sessizce return etseydik sesliyi açmanın tek yolu başka bir preset'e geçip tüm zamanlamayı ezmek olurdu.
- **Sihirbaz yolu tuzağı (düzeltildi):** `KurulumSihirbaziSayfasi` preset'i `...HATIRLATMA_PRESETLERI[y]` diye **spread ediyordu** → store'a yalnız `esikler`/`sikliklar` (+ `aciklama`/`ikon` çöpü) gidiyor, `matris` ise reducer içinde `eskidenMatriseGoc` ile türetiliyordu; **o göç `mod`'u DAİMA `'bildirim'` sabitler** → sihirbazdan geçen kullanıcıda sesli preset'lerin anons adımı hiç çalışmıyordu. Doğrusu: **`presetAyarlariniOlustur(yogunluk)`** (`muhafizSlice`) — `matris`i preset'ten DOĞRUDAN üretir, payload'da geldiği için reducer yeniden türetmez, sesli preset'te `sesliOnayi: true` de işaretler (sihirbaz kartı sessiz mod/DND davranışını açıkça yazar = bilgilendirilmiş onay). Preset'i ham spread etme; her yeni tüketici bu yardımcıdan geçmeli. Nöbetçi test: "REGRESYON: reducer eski-alan senkronu sihirbazın modunu EZMEZ".
- **Bir kerelik preset göçü YALNIZ ZAMANLAMA TAŞIR (`esikDk` + `siklik`) — `mod`/`acilKanal`/`bildirimSesi`/`anonsMetni`'ye DOKUNMAZ.** Göç olmasaydı preset'lerin asıl kazancı (yoğun 15→7 uyarı/vakit) mevcut kullanıcıların **hiçbirine** ulaşmazdı; ama `presetUygula` ile göç etmek kullanıcının emeğini ezer → göç `presetZamanlamasiniUygula` (`core/muhafiz/matrisIslemleri.ts`) kullanır. **Neden kritik:** bu projede mod değişikliği yoğunluğu `'ozel'` YAPMAZ (`zamanlamaDegistiMi` yalnız eşik+sıklık bakar, spec 4.1) → "Yatsı'yı elle susturmuş ama yoğunluğu hâlâ 'normal'" kullanıcı `yogunluk !== 'ozel'` kapısından **GEÇER**; mod ezilseydi seçimi sessizce geri alınır ve göç `ozelMatrisYedegi` yazmadığı için **geri dönüş de olmazdı**. Aynı sebeple **sesli hücreler göçle AÇILMAZ** (`sesliOnayi` ne okunur ne yazılır) — rıza yalnız ekranda `SesliOnayModal` ile alınır. Tek istisna: diskteki matris yapısal olarak bozuksa korunacak bir şey yoktur → preset'ten sıfırdan kurulur (sesli kapalı).
- **Göç mekaniği: bayrak `muhafizAyarlariniYukle` thunk'ında, ayar nesnesinin İÇİNDE** (`presetGocuYapildi?: boolean`) — ayrı `Depolama` anahtarı + `migrasyonyiGarantile` deseni SEÇİLMEDİ; muhafız ayarları zaten tek bir JSON blob'u ve thunk onu her açılışta okuyor, ikinci anahtar gereksiz olurdu. İki kritik ayrıntı: **(a)** `initialState.presetGocuYapildi = true` — taze kurulum zaten güncel preset'le başlar, dolayısıyla bu state'ten üretilen her disk kaydı (sihirbaz dahil) bayrağı taşır ve göç **yalnız bayrağı olmayan eski kayıtlarda** çalışır; **(b)** göç uygulandığında thunk sonucu **hemen `AsyncStorage.setItem` ile diske yazar** — reducer'ın bir sonraki yazımını bekleseydi göç her açılışta yeniden çalışır ve kullanıcının elle yaptığı mod/ses değişikliklerini sürekli geri alırdı. Yalnız tiplenmiş alanları yazmak bilinmeyenleri **siler** → konumu yalnız bu blob'da olan eski kullanıcıda arka plan görevi varsayılan İstanbul'a düşer ve **bildirimler yanlış vakitlere planlanır**. ## CI / Sürümleme
- APK = **Gradle** (`android-build.yml`), AAB = **EAS** (`expo-build.yml`) → Play Store internal track.
- `android-build.yml` reusable'dır ve `ci.yml`'in `auto-release` job'undan çağrılır. **Reusable'ın istediği izinler caller job'un izinlerinin ALT KÜMESİ olmalı** → `actions: write` hem `android-build.yml`'de hem `auto-release`'te gerekli, yoksa `startup_failure`.
- Release sırası: önce **GitHub Release yayınla**, EN SON EAS dispatch.
- `eas.json`: `appVersionSource: local`; sürüm numarasını CI yönetir.
- **`paulhatch/semantic-version` deseni DÜZ METİNDİR — eğik çizgiyle sarılmadıkça regex DEĞİL.** `minor_pattern: "feat:"` yazılıydı ve bu repodaki commit'ler KAPSAMLI (`feat(cuma):`, `feat(muhafiz):`) olduğu için `feat:` alt dizesi hiçbirinde geçmiyordu → **0.23.0'dan beri 42 özellik commit'ine rağmen minor bump HİÇ tetiklenmedi**, sürüm 0.23.0 → 0.23.27 hep patch olarak arttı ("0.24'ü bir türlü çıkaramıyoruz"). Doğrusu `minor_pattern: '/^feat(\(.+\))?!?:/'` — **TEK tırnak** şart: YAML çift tırnaklı dizede `\(` geçersiz kaçış dizisidir ve workflow parse edilmez. `^` ile satır başına sabitle, yoksa `search_commit_body: true` açıkken gövdede geçen "feat" yanlış bump üretir. `major_pattern: "BREAKING CHANGE:"` düz metin olarak zaten doğru.
- **EAS kuyruğu 2 saati aşabilir → `eas build`'i bekleyen adım job'u DÜŞÜRMEMELİ.** v0.23.27'de yaşandı: kuyruk **114 dk** sürdü (build'in kendisi 14 dk), job'un `timeout-minutes: 90`'ı doldu, build adımı `cancelled` oldu ve submit koşulu `steps.aab_build.outcome == 'success'` tutmadığı için **EAS'te BAŞARIYLA BİTEN** build Play internal track'e hiç gönderilmedi. Kural: build adımına `continue-on-error: true` + kendi `timeout-minutes`'ı ver (job timeout'u ondan BÜYÜK olmalı), sonra gerçek durumu **EAS'e sor** (`eas build:list --limit 1 --json`, `appBuildVersion` ile beklenen versionCode'u eşleştir) ve submit'i adımın outcome'una değil **o duruma** bağla. Adım çıktısına güvenen özet metni de aynı şekilde yanıltıcı olur. `sadece_submit` girdisi biten bir build'i sonradan göndermeye yarar (yeniden build gerekmez).
- **master'a HER merge bir release keser (~24 dk).** `auto-release` her master push'unda (`paths-ignore: **.md/docs/LICENSE` hariç) çalışır; `paulhatch/semantic-version` `chore:` dahil her commit'te en az **patch bump** yapar → imzalı APK + Play Store internal. `ci.yml` `concurrency: cancel-in-progress: true` → arka arkaya merge'de sonraki push öncekinin release'ini **iptal eder**; bu yüzden merge'ler **serileştirilmeli** (her run bitmeden sonrakini merge etme). Release commit'i (`chore(release): X [skip ci]`) `package.json`+`package-lock.json`+`app.json`+`build.gradle`+`UygulamaSabitleri.ts`+`CHANGELOG.md`'yi değiştirip push'lar → açık tüm dependabot/lockfile PR'larını çakıştırır (rebase gerekir). **Çoklu PR merge'inde:** ardışık N release'ten kaçınmak için ilişkili/dependabot PR'larını tek dalda birleştir (tek tutarlı lockfile → `npx -y npm@10 ci` ile doğrula → tek release). `.md`-only commit'i doğrudan master'a push edebilirsin (release *tetiklemez*). **Araya kaçan push'a karşı "Commit ve Tag" adımı artık dayanıklı** (PR #170): `pull --rebase --autostash` + 3 denemeli retry var; eskiden çıplak `git push origin HEAD:master` yüzünden master araya kaçan bir push'la ilerlerse push **non-fast-forward reddedilir** (`! [rejected] HEAD -> master (fetch first)`) → release başarısız olur, APK/tag/Release kesilmezdi (yaşanmıştı: docs spec push'u uçuştaki release'i kırdı). Yine de gereksiz yere uçuştaki release'e push atma; rebase **çakışırsa** (ör. CHANGELOG.md'ye dokunan bir docs push'u) adım bilinçli olarak **abort + hata** verir, sessizce geçmez.
- **Release adımında TAG, push'tan SONRA atılır — sırayı bozma (sinsi tuzak).** `git tag` push'tan önce atılırsa `pull --rebase` release commit'ini **yeniden yazar**, tag ise eski **yetim** commit'te kalır → `git push origin <tag>` master'da olmayan bir commit'i etiketler ve GitHub Release oraya bağlanır. Doğru sıra: commit → rebase+push (retry) → **sonra** tag → tag push. Yerel git sandbox'ında yarış simüle edilerek üç senaryo da doğrulandı (eski mantık reddediliyor / yeni mantık tag'i master'da tutuyor / tag-önce varyantı yetim commit üretiyor).
- **Shell testinde `git push | grep` KULLANMA:** `set -o pipefail` boru hattına `git push`'un exit kodunu verir; `grep` eşleşse bile `if` yanlış dala gider → "push geçti" gibi **yanıltıcı** sonuç alırsın (bu tuzağa düşüldü). Çıktıyı önce değişkene al, exit kodunu ayrı kontrol et.

- **Node 20** kullan (CI pin'i ile aynı; `package.json > engines.node >= 20.19.4`).
- `npm ci`/`npm install` **`postinstall: patch-package`**'i çalıştırır → `patches/` git'te, taze VM'de yamalar otomatik uygulanır; bu adımı **ATLAMA** (yoksa `react-native-css-interop` sessizce bozulur).
- **PR hedef dalı: `master`** (develop değil).
- Jules `git push` kullanıyorsa panelde **`CI=true`** env tanımla → `.githooks/pre-push` push'ta `verify`'ı gereksiz yere tekrar koşmaz (Jules GitHub App API ile PR açıyorsa hook tetiklenmez, gerek yok).
